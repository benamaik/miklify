# Miklify

Десктопный плеер для **вашей локальной музыки** (mp3 / flac / wav / ogg / m4a) в строгом монохромном оформлении (графит, серый, белый) и с анимированными фонами, которые пульсируют в такт музыке. Без стриминга и без загрузок из интернета.

## Стек и почему

**Electron + чистые HTML/CSS/JS** (без фреймворков и сборщиков).
- Chromium сам воспроизводит все нужные форматы, включая FLAC и M4A, а Web Audio даёт данные для реакции фона на музыку.
- Трей, медиаклавиши Windows и сборка в `.exe` (electron-builder) работают из коробки.
- Теги читает библиотека `music-metadata`. Нативных модулей нет, поэтому ничего не нужно компилировать.

## Запуск (одной командой)

Нужен Node.js 22.12 или новее. При первом запуске Electron скачается сам.

```bash
npm install
```

```bash
npm start
```

`npm start` запускает плеер отдельно от консоли: окно терминала можно сразу закрыть, музыка продолжит играть. При первом запуске рядом с `electron.exe` создаётся копия `Miklify.exe` с нашим названием и значком (через `rcedit`), поэтому в диспетчере задач процесс называется «Miklify», а не «Electron». Собранный `.exe` называется Miklify и без этого. Для отладки с логами в консоли есть `npm run dev`.

**Запуск вообще без консоли.** Создайте ярлык один раз:

```bash
npm run shortcut
```

Ярлык «Miklify» появится на рабочем столе и в папке проекта. Он запускает плеер напрямую, без окна терминала. Собранный `.exe` (см. ниже) тоже работает без консоли.


## Сборка в .exe

```bash
npm run dist
```

В папке `dist/` появятся установщик `Miklify Setup 1.0.1.exe` и переносимая версия `Miklify 1.0.1.exe`. Другу достаточно отправить любой из этих двух файлов, Node.js ему не нужен.

> Если сборка падает с `Cannot create symbolic link` при распаковке `winCodeSign`, это значит, что Windows не даёт обычному пользователю создавать символические ссылки (они нужны только для macOS-файлов внутри архива). Есть два решения: запустить терминал от имени администратора или включить «Режим разработчика» в параметрах Windows. Третий вариант: переименовать уже распакованную папку в `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\` в `winCodeSign-2.6.0` и запустить сборку снова. Иконка лежит в `assets/icon.png`; пересоздать её можно командой `npm run icon`.

## Как проверить по этапам

**Этап 1 (ядро).** Запустите приложение и нажмите «Выбрать папки». В боковой панели появится прогресс сканирования, после него треки покажутся в «Библиотеке». Двойной клик по строке запускает трек. Внизу работают play/pause, следующий/предыдущий, перемотка, громкость, перемешивание и повтор (выкл → всё → один трек).

**Этап 2 (библиотека).** Откройте «Исполнители» и «Альбомы» (это карточки с обложками) и «Поиск», который фильтрует при вводе. Правый клик по треку → «Играть следующим» / «В конец очереди». Кнопка очереди в плеере открывает очередь, порядок меняется перетаскиванием. Закройте и откройте приложение снова: библиотека загружается из кэша мгновенно.

**Этап 3 (плейлисты и удобство).** Кнопка «+» в боковой панели или правый клик → «Добавить в плейлист → Новый плейлист…». На странице плейлиста есть «Переименовать» и «Удалить». Сердечко добавляет трек в «Любимые треки». Крестик окна сворачивает приложение в трей, музыка продолжает играть. Проверьте медиаклавиши и меню трея. После перезапуска восстанавливаются громкость, трек, позиция и очередь.

**Этап 4 (красота).** «Настройки» (пункт в боковой панели или кнопка справа сверху): тёмная/светлая тема и анимированный фон (Аврора, Частицы, Волны, Звёзды, Выкл). Всё оформление монохромное, цветными остаются только сами обложки альбомов. У играющего трека в списке анимируется мини-эквалайзер.

## Настройки и эквалайзер

На странице «Настройки» собраны:
- **Внешний вид**: тема, стиль анимированного фона и переключатель «Фон реагирует на музыку».
- **Эквалайзер**: 10 полос от 32 Гц до 16 кГц, каждая от −12 до +12 дБ. Левые ползунки отвечают за низкие частоты (бас), правые за высокие. Есть пресеты «Ровный», «Больше баса», «Больше высоких», «Вокал», «Рок», «Электроника» и «Классика». Если подвинуть любой ползунок, включается пресет «Свой». При подъёме полос общий уровень немного снижается, чтобы звук не хрипел. Кнопка с полосками в плеере сразу открывает эквалайзер.
- **Библиотека**: папки с музыкой и пересканирование.
- **Поведение**: сворачивать ли приложение в трей при закрытии окна.
- Список горячих клавиш.

Все настройки сохраняются между запусками.

## Онлайн: YouTube, свободная музыка и радио

### YouTube (поиск любой песни)

Вкладка «Онлайн» → «YouTube». Поиск идёт через **официальный YouTube Data API**, а играет трек **встроенный плеер YouTube** (официальный IFrame Player). Звук с YouTube не скачивается и не извлекается: это разрешено правилами YouTube и работает у всех.

- Без запроса показываются популярные музыкальные ролики вашей страны, с запросом — поиск по музыкальной категории (только ролики, которые разрешено встраивать).
- Результаты ставятся в очередь, лайкаются и добавляются в плейлисты, смешиваясь с вашими файлами. После перезапуска очередь и позиция восстанавливаются.
- Поиск запускается по **Enter**, а не при каждой букве: у бесплатной квоты YouTube около 100 поисков в день на ключ.
- Видео показывается в панели справа внизу, пока играет трек с YouTube. По правилам YouTube панель нельзя прятать или делать меньше 200×200, поэтому она всегда на виду. Там же ссылка «Открыть на YouTube».
- Панель можно **перетащить за нижнюю полосу** в любое место окна Miklify (за границы окна она не уйдёт). Двойной клик по полосе возвращает её на место. Положение запоминается между запусками.
- Собственные элементы управления YouTube (шестерёнка настроек, полноэкранный режим, панель перемотки, затемнение, подсказки поверх видео) отключены штатными параметрами плеера: играть, перематывать и менять громкость нужно кнопками Miklify. Название ролика, которое YouTube иногда показывает сверху при наведении, убрать нельзя: это часть его плеера.
- У роликов бывает реклама YouTube. Эквалайзер и реакция фона на музыку YouTube не действуют: плеер YouTube не отдаёт звук приложению.
- **Что нельзя проиграть, Miklify определяет сам.** API YouTube про многие ролики сообщает «встраивать можно», а плеер всё равно отказывается играть (права правообладателей, страна, возраст), и по данным API это не угадать. Поэтому сначала отсеиваются ролики с явным запретом встраивания, возрастным ограничением и эфиры, которые ещё не начались. Затем, после каждого поиска, плеер YouTube на секунду-другую по очереди подгружает каждый результат **без воспроизведения**: недоступные он отвергает за доли секунды (на 30 роликов уходит несколько секунд), и такие ролики пропадают из списка. Окно проверки показывается на экране с индикатором, пока идёт проверка, а обычное воспроизведение при этом не прерывается. Проверку можно выключить в «Настройки» → «Данные YouTube».
- Если плеер отказывается играть ролик уже во время воспроизведения (ошибки 100/101/150/153), Miklify переходит к следующему треку и запоминает отказ. В списках лайков и плейлистов такой трек становится приглушённым с пометкой «недоступно на YouTube», а очередь, «Вперёд», «Назад» и запуск списка проходят мимо него без ожидания. Запись об отказе хранится 30 дней, потом ролик можно проверить заново; сбросить её можно кнопкой «Данные YouTube» в настройках.
- **Шортсов в результатах нет.** У YouTube API нет отдельного признака Shorts, поэтому отсеиваются ролики не длиннее минуты и ролики с пометкой #shorts в названии, описании или тегах. Песня короче минуты тоже будет отсеяна, зато сами Shorts не попадут в список.
- Ключ нужен бесплатный и свой, прямо во вкладке покажется форма с инструкцией: Google Cloud Console → проект → включить **YouTube Data API v3** → Credentials → API key. Он хранится только на вашем компьютере. Не вписывайте ключ в `src/config.js`, если код публикуется: правила YouTube запрещают ключи в open source проектах.
- Перед первым использованием YouTube нужно принять политику конфиденциальности и условия YouTube. Текст есть в приложении (ссылка внизу боковой панели) и в [PRIVACY.md](PRIVACY.md).
- Пока окно скрыто или свёрнуто, YouTube стоит на паузе, а когда окно возвращается, продолжает играть: правила запрещают фоновое воспроизведение. Свои файлы и радио в фоне играют как обычно.
- Данные о роликах хранятся не дольше 30 дней. На 25-й день те, что лежат в лайках, плейлистах или очереди, обновляются при запуске, а неиспользуемые удаляются. Удалённые с YouTube ролики исчезают из списков. Если рабочего ключа нет, данные старше 30 дней удаляются. При лимите квоты или сбое сети обновление повторится при следующем запуске. Всё сразу удаляется кнопкой в «Настройки» → «Данные YouTube».
- Плеер YouTube открывается из локальной страницы `http://127.0.0.1:<порт>` (простой сервер Miklify, доступный только вашему компьютеру), потому что YouTube не встраивается в страницы `file://`.

### Свободная музыка и радио

Раздел «Онлайн» в боковой панели. Оба источника легальные.

**Радио** (каталог Radio Browser, около 50 тысяч станций, ключ не нужен)
- Без запроса показываются популярные станции. Искать можно по названию или жанру: jazz, rock, news, lofi.
- Клик по карточке включает станцию. Сердечко добавляет её в «Избранные станции».
- Эквалайзер и реакция фона на музыку работают и для радио. Перемотки нет, вместо длительности написано «ЭФИР».

**Музыка** (Jamendo: полные треки независимых музыкантов под Creative Commons)
- Без запроса показывается популярное за неделю, можно искать по треку, исполнителю или жанру.
- Онлайн-треки играют, ставятся в очередь, лайкаются и добавляются в плейлисты так же, как локальные, и сохраняются после перезапуска.
- В меню «⋯» есть «Скачать в библиотеку», если автор разрешил скачивание. Файл ляжет в «Музыка\Miklify», и эта папка сама добавится в библиотеку. Там же можно открыть лицензию трека.
- Нужен ключ приложения (Client ID). Если ключа нет, вкладка «Музыка» сама покажет форму: короткая инструкция, поле для Client ID и кнопка «Подключить». Ключ сразу проверяется: неверный Jamendo не примет, и форма об этом скажет. Хранится он только на этом компьютере, сменить его можно ссылкой «Сменить ключ Jamendo» под списком треков.
- Если хотите, чтобы в собранном `.exe` Jamendo работал у всех без ввода ключа, задайте секрет `JAMENDO_CLIENT_ID` для сборки релиза (см. раздел «Выпуск релиза»). В репозитории `src/config.js` остаётся пустым. Ключ, введённый во вкладке, главнее встроенного.

Почему не Spotify и не ВК: их правила не разрешают играть их музыку в сторонних плеерах без Premium и особой лицензии, а открытого API для этого нет. Audius проверяли: поиск работает, а полное воспроизведение без ключа больше не отдаётся. Скачивание звука с YouTube в Miklify намеренно не делается: оно нарушает правила сервиса и авторские права.

## Распознавание исполнителей

Если в файле нет тегов, Miklify может узнать трек по звуку. Утилита Chromaprint (`fpcalc`) снимает «отпечаток» первых двух минут, база AcoustID находит по нему запись, а MusicBrainz и Cover Art Archive дают исполнителя, название, альбом и обложку. В интернет уходит только отпечаток, музыка остаётся на диске. Функция выключена, пока вы сами её не запустите.

Как включить:
1. Скачайте `fpcalc.exe`. Это официальный релиз Chromaprint 1.5.1 с GitHub, около 1,5 МБ, он ляжет в папку `bin/`:
   ```bash
   npm run get-fpcalc
   ```
2. Ключ AcoustID нужен **один на всё приложение**, пользователям свой получать не надо. Разработчик один раз регистрирует приложение на acoustid.org/new-application (это мгновенно, без модерации) и задаёт секрет `ACOUSTID_KEY` для сборки релиза. После этого у всех, кто скачал релиз, распознавание работает сразу. При сборке из исходников ключ вводится в поле в настройках.
3. Нажмите «Распознать». Прогресс видно в настройках и в боковой панели, остановить можно той же кнопкой.

Подробности:
- Распознаются только треки, у которых в тегах нет исполнителя. Настоящие теги никогда не перезаписываются.
- Найденные данные хранятся в `%APPDATA%\Miklify\overrides.json`, а не в самих файлах, и сохраняются после пересканирования.
- Треки, которые не нашлись, повторно не проверяются. Кнопка «Повторить не найденные» даёт им ещё одну попытку.
- AcoustID пропускает до 3 запросов в секунду, поэтому 1000 треков распознаются примерно за 5–10 минут.
- Засчитываются только совпадения с уверенностью от 60%, иначе трек остаётся «неизвестным».
- В собранный `.exe` (`npm run dist`) `fpcalc.exe` попадает автоматически, если он лежит в `bin/`.

## Выпуск релиза

Релиз собирается на GitHub Actions ([.github/workflows/release.yml](.github/workflows/release.yml)), когда в репозиторий приходит тег:

```bash
git tag v1.0.1
```

```bash
git push origin v1.0.1
```

Сборка скачает `fpcalc.exe`, запишет ключи из секретов в `src/config.js`, соберёт `.exe` и создаст релиз на GitHub. Секреты задаются в Settings → Secrets and variables → Actions: `ACOUSTID_KEY` и `JAMENDO_CLIENT_ID`. Без них сборка тоже пройдёт, просто эти функции будут просить ключ. Ключ YouTube в сборку намеренно не передаётся.

`.exe` не подписан, поэтому Windows может показать предупреждение SmartScreen, пока не будет куплен сертификат подписи кода.

## Принятые решения по умолчанию

- **Кэш**: JSON-файлы, а не SQLite, чтобы не было нативных модулей. Файлы лежат в `%APPDATA%\Miklify\`: `library.json` (теги), `settings.json` (настройки, плейлисты, лайки, очередь) и папка `covers/` (обложки). При повторном сканировании теги перечитываются только у изменённых файлов (сравниваются дата изменения и размер).
- **Исполнители** группируются по тегу «исполнитель» трека, **альбомы** по паре «исполнитель альбома + название».
- **Файлы без тегов**: названием становится имя файла, исполнитель и альбом получают значения «Неизвестный исполнитель» / «Неизвестный альбом».
- **Перемешивание** играет каждый трек очереди по одному разу в случайном порядке, потом останавливается (с «повторять всё» начинается новый круг). «Назад» возвращает к ранее сыгранным.
- **Края очереди**: «Следующий» на последнем треке и «Назад» на первом останавливают музыку, а не перескакивают на другой конец. По кругу очередь идёт только в режиме «повторять всё». «Назад» на середине трека (после 3 секунд) сначала возвращает к его началу.
- **Плавное затухание**: пауза, переключение и остановка не обрывают звук, он стихает примерно за 0,3 секунды, а при продолжении так же плавно возвращается. Название нового трека меняется сразу, поэтому быстро листать можно без задержек: заиграет последний выбранный. Для YouTube плавно меняется громкость его плеера.
- **Зажатые клавиши**: пробел, M, L и Ctrl+стрелки срабатывают один раз на нажатие. Перемотка стрелками и громкость при удержании повторяются.
- **Длительность**: если у трека она неизвестна, в списке стоит «—», а при первом запуске трека значение берётся у плеера и запоминается. Прямые эфиры YouTube показываются как «ЭФИР», перемотки у них нет.
- **Повторный запуск**: кнопка «Играть» у трека, альбома, плейлиста или станции, которые уже играют, ставит паузу или продолжает, а не начинает заново.
- **Закрытие окна** по умолчанию сворачивает приложение в трей (это можно отключить в настройках). Полный выход через меню трея → «Выход».
- **При запуске** библиотека тихо пересканируется в фоне, чтобы подхватить новые файлы.
- **Удалённые файлы** пропадают из библиотеки и очереди. В лайках и плейлистах их id сохраняются и снова появятся, если файл вернётся.
- **Визуализация**: вместо отдельного эквалайзера фон реагирует на низкие частоты, а у играющего трека показывается мини-эквалайзер.
